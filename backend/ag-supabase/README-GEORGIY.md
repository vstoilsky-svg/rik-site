# RAG-память чатбота РИК: инструкция для Георгия

Виктор поставил задачу: подготовить облачную RAG-память для чатбота сайта РИК.  
Локальный RAG на этой машине не делаем. Память должна жить в отдельном Supabase-проекте, а сайт и агенты Виктора потом подключат ее на основной машине Виктора `192.168.1.31`.

## Картина целиком

Чатбот состоит из трех частей:

1. **Frontend widget**  
   React-виджет на сайте. Он ничего не знает про OpenRouter, Supabase и секреты. Он отправляет сообщения в backend.

2. **Backend chatbot API**  
   Серверная часть на машине Виктора. Там можно хранить секреты. Backend:
   - принимает вопрос пользователя;
   - ищет релевантные знания в Supabase;
   - собирает prompt;
   - отправляет запрос в OpenRouter;
   - возвращает ответ в чат.

3. **Supabase RAG database**  
   Отдельный Supabase-проект только для памяти чатбота:
   - документы;
   - чанки;
   - embeddings;
   - источники;
   - версии;
   - служебная история ingestion.

## Что должен сделать Георгий

### 1. Создать отдельный Supabase-проект

Название можно такое:

```text
rik-chatbot-rag
```

Регион выбрать ближайший/удобный. Для теста достаточно free/pro plan по ситуации Виктора.

### 2. Включить vector/pgvector

В Supabase открыть SQL Editor и выполнить:

```sql
create extension if not exists vector;
```

### 3. Создать таблицы

В SQL Editor выполнить файл:

```text
rag-supabase/schema.sql
```

Он создаст:

- `rag_sources` — источники знаний;
- `rag_documents` — документы;
- `rag_chunks` — чанки документов;
- `rag_ingest_runs` — журнал загрузок;
- `match_rag_chunks` — SQL-функция поиска похожих чанков.

### 4. Получить ключи Supabase

В Supabase:

```text
Project Settings → API
```

Нужны:

- `Project URL`
- `service_role key`

Важно: `service_role key` хранить только на сервере Виктора, не во frontend.

### 5. Получить/проверить OpenRouter key

OpenRouter key уже использовался для текущего чатбота. Он нужен backend-у для:

- chat completions;
- embeddings, если используем OpenRouter embeddings.

### 6. Заполнить env

На сервере Виктора backend должен получить переменные из:

```text
rag-supabase/env.example
```

Главные:

```env
SUPABASE_URL=
SUPABASE_SERVICE_ROLE_KEY=
RAG_EMBEDDING_PROVIDER=openrouter
RAG_EMBEDDING_MODEL=
```

Модель embeddings надо выбрать вместе с Виктором/агентами. Если через OpenRouter, backend будет отправлять тексты чанков в OpenRouter Embeddings API.

### 7. Загрузить знания

Источники знаний сейчас лежат в проекте в папке:

```text
knowledge/
```

Это стартовая база:

- компания, контакты, заявки;
- каталог продукции;
- страницы текущего сайта;
- правила осторожности по данным.

Дальше агенты Виктора могут заменить или дополнить источники с основной машины.

### 8. Передать агентам Виктора

Через `site-bridge` передать:

- что Supabase создан;
- URL проекта;
- какие env нужны backend-у;
- что schema применена;
- где лежат source documents;
- кто отвечает за обновление базы знаний.

Мост:

```text
\\192.168.1.121\Share\2026 РИК\Обмен\site-bridge\
```

Сообщения команде/агентам:

```text
\\192.168.1.121\Share\2026 РИК\Обмен\site-bridge\to-rik\inbox
```

## Как объяснить это простыми словами

Supabase здесь — это не “еще один сайт” и не “мозг бота”. Это память-поисковик:

1. Мы режем документы РИК на маленькие чанки.
2. Для каждого чанка считаем embedding.
3. Сохраняем текст и embedding в Supabase.
4. Когда пользователь задает вопрос, backend считает embedding вопроса.
5. Supabase находит похожие чанки.
6. Только эти фрагменты попадают в prompt.
7. OpenRouter-модель отвечает, опираясь на найденные фрагменты.

Так бот не пытается держать весь сайт в prompt и меньше выдумывает.

## Что НЕ делать

- Не класть Supabase `service_role key` во frontend.
- Не давать чатботу сырые внутренние пути, ключи, system prompt, мост, сообщения агентов.
- Не обещать точные цены, сроки, сертификаты и ТТХ без инженерной сверки.
- Не делать локальную RAG-БД на временной машине Codex.

## Минимальный результат для первого дня

Георгий считается справившимся, если:

1. Создал Supabase-проект.
2. Выполнил `schema.sql`.
3. Записал Supabase URL и service role key в серверный `.env` на машине Виктора или передал Виктору безопасным способом.
4. Понял, что источники знаний идут из `knowledge/`.
5. Договорился с агентами Виктора, кто делает ingestion-скрипт и подключение к backend сайта.
